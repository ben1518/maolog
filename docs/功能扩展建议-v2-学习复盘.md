# 「楚师智学」功能扩展建议 v2：从「记录属于你」到「你能用它复盘」

> 面向「AI 赋能校园」主题，在一期屏幕感知引擎与 v1.0 校园功能建议之上，补充学生侧的学习复盘能力，以及支撑它的数据边界设计。
>
> 本文是主方案书的**答辩附录**，不是第二份参赛方案，也不替代 `功能扩展建议-AI赋能校园.md`。
>
> 复用成本：S＝主要复用现有数据与统计；M＝需要新的规则、界面或导出；L＝需要新的系统边界。

> **定位修订（2026-10-28）**：这份文档最初叫「学生自保侧」，落点是"让记录可被学生自己掌控"。
> 但自保回答的是"凭什么信你"，不是"怎么帮我学"——放在主线上会跑题。
> 因此对外主入口改为**学习复盘**：同一批行为数据，输出从"过程证据"改成"节奏结论 + 卡点 + 下一步"。
> 本文余下章节仍然有效，但角色从并列卖点降为**支撑层**：它们解释这套复盘为什么不越界、数据去了哪里。
>
> **原型状态（2026-10-28）**：代码在 `core/attest.py`、`core/learning_review.py`、`core/ai_profile.py`、`core/outbound.py`、`core/time_estimate.py`、`core/v2_runtime.py`、`core/v2_demo.py`、`ui/study_review_dialog.py`、`ui/ai_profile_dialog.py`、`ui/time_estimate_dialog.py`、`ui/v2_preview.py`、`ui/v2_settings.py`，测试 `tools/test_v2.py`。主窗口已接入“学习复盘”“AI 协作”“估时校准”“演示看板”和“设置 → 数据护照…”。**实盘外发台账默认关闭；演示看板只读写隔离的 `data/v2_demo/`，不读取真实记录。**

## 0. 一页纸：结论先行

v1.0 解决的是**所有权**：记录只属于学生本人。

v2 解决的是**使用权**：既然记录属于你，就应该拿来帮你把学习看清楚，而不只是躺着。

对外的主线只有一句话：**同一段时间，先看它是怎么过去的，再决定下次怎么过。**

| 能力 | 原来的说法 | 现在对外怎么说 | 对学生的实际用处 |
|---|---|---|---|
| 过程整理 | 学习过程存证：导出一份可核对的材料 | **学习复盘**：节奏、卡点、下一步 | 知道自己什么时候状态最好、在哪被打断 |
| AI 协作 | AI 使用声明：说明我是怎么用 AI 的 | **AI 用法回看**：先想后问还是直接要答案 | 分清哪部分是自己做的，下次怎么用 |
| 估时 | 时间感知校准 | **估时校准**：计划与实际差多少 | 把计划写得更接近现实 |
| 数据台账 | 数据护照：哪些数据出过本机 | 保留，收进设置页 | 知道数据去了哪里（支撑层） |

一句话：**前三个是照镜子，第四个是看门。镜子放在桌面上，门锁装在门后面。**

## 0.1 原来那套论证（保留，作为支撑层）

v2 原本要解决的是**处分权**：因为记录属于你，所以你才有权决定把哪一段拿出去、以什么形式拿出去。

三个功能不是并列卖点，而是同一句话的三个动作：

```text
AI 协作画像：看清“我和 AI 怎样一起做完” ──┐
                                          ├─→ 学习复盘：把这段过程整理成结论
数据台账：看清“哪些数据出过本机” ────────┘    学生审阅、删改、导出、撤回
```

| 功能 | 一句话价值 | 成本 | 建议 |
|---|---|---:|---|
| 学习复盘 | 把一次作业、论文或项目的过程整理成节奏结论和下一步，而不是给出文本检测结论 | S | 优先 |
| AI 协作画像与使用回看 | 描述“先思后问、边做边问、直接要答案”三种行为模式，支持查看依据与手动改判 | S/M | 优先 |
| 数据台账与数据护照 | 让学生看到本程序每次外发的时间、对象、大小与用途，并导出一份可检查的数据说明 | S | 支撑层 |
| 时间感知校准 | 开工前估计、日终对照，累积“我以为”和“实际”的偏差 | S | 彩蛋 |

本文还主动否掉两个看似校园化、实则不成立的选题：**新生适应期观察**与**竞赛／大创团队过程纪实**。原因不是技术做不出来，而是它们分别会带来重复建设、错误标签和新的数据汇聚风险。

## 1. 为什么这一版只做学生侧

### 1.1 三个筛选判据

新功能必须同时满足：

1. **学生自己愿意开**：不用行政要求，也有个人收益。
2. **不需要学校数据**：不接教务、一卡通、门禁或心理系统，也能独立运行。
3. **不产生对他人的评价**：不判断谁努力、谁优秀、谁有问题。

这三条把“赋能校园”落到一个更基础的前提：学校侧的应用要成立，先得有学生愿意长期使用的一手数据。没有自愿使用，后面的聚合、报告和教学反馈都只是空壳。

### 1.2 与 v1.0 的关系

v1.0 主要回答“**学校拿它干什么**”：班级聚合、课程反馈、师范生训练。

v2 回答“**学生凭什么让它记录**”：记录能帮助我回看、整理和说明自己的学习过程，而且我知道数据去了哪里。

二者共用同一个引擎，但不互相替代：

- v1.0 的**成果归档**整理“我做成过什么”；
- v2 的**过程存证**整理“我是怎么做成的”；
- v1.0 的**专注力体检**描述时间与注意力；
- v2 的**AI 协作画像**描述人与 AI 的分工；
- v1.0 的**集体授权**是一条原则；
- v2 的**数据台账**把原则变成学生能检查的界面。

语气上也要划清界限：这不是学生与学校对抗，而是**配合合理的教学要求，但不把学生置于“先被怀疑、再想办法解释”的位置**。

## 2. 能力盘点：现有数据到底能说明什么

### 2.1 `snapshots` 字段级能力表

以下以现有 `core/storage.py` 的真实字段为准，不假设已有文件级或键鼠级数据。

| 现有字段 | 可以支持 | 不能据此推出 |
|---|---|---|
| `ts` / `day` | 活动先后、跨天跨度、中断与回访、阶段交替 | 每一段都等于真实有效投入 |
| `app_name` | 区分文档工具、浏览器、IDE、AI 客户端等应用类别 | 具体写了哪句话、改了哪个字 |
| `window_title` | 识别同一文档标题的再次出现；辅助识别 AI 网页或工具 | 标题之外的任务；标题缺失时的可靠归类 |
| `category` / `activity` | 把查阅、写作、编程、视频学习等段落串成语义序列 | 文件保存次数、版本差异、内容原创性 |
| `detail` | 给学生本人提供回看线索 | 可直接放进公开材料的客观事实 |
| `focus_score` / `is_productive` | 学生本人的复盘参照 | 思考深度、能力高低、任务难度 |
| `status` / `error` | 判断某段时间的数据是否完整、是否存在识别失败 | 把缺数据解释成“没有学习” |
| `image_path` / `thumb_path` | 学生本人按需核对当时画面 | 默认进入导出材料，或交给其他角色 |

**一个必须写清的缺口**：现有表没有文件内容、保存事件和版本历史，因此不能直接给出“修改次数”。可用替代指标是**同一文档标题在窗口序列中的回访次数**。它是行为层近似，不是文件层事实，界面与导出物都要这样标注。

### 2.2 三条硬边界

1. **不读取或导出作业正文**：过程材料只使用行为元数据，正文始终由学生自己处理。
2. **不向其他角色自动上报个体记录**：默认没有教师端个人列表，也没有班级个人排行。
3. **不产出能力、态度或品德分数**：只描述过程与模式，不给人下结论。

### 2.3 最小新增数据表

只新增表，不修改现有 `snapshots` 与 `daily_summary` 的字段：

```sql
CREATE TABLE IF NOT EXISTS ai_use_daily (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    day           TEXT NOT NULL,
    task_context  TEXT NOT NULL,
    start_ts      TEXT NOT NULL,
    end_ts        TEXT NOT NULL,
    mode          TEXT,
    original_mode TEXT,
    evidence_json TEXT,
    overridden    INTEGER NOT NULL DEFAULT 0,
    created_at    TEXT NOT NULL DEFAULT (datetime('now', 'localtime')),
    updated_at    TEXT
);

CREATE UNIQUE INDEX IF NOT EXISTS ux_ai_use_task_day
    ON ai_use_daily(day, task_context);

CREATE TABLE IF NOT EXISTS outbound_log (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    ts          TEXT NOT NULL,
    provider    TEXT,
    model       TEXT,
    bytes       INTEGER,
    has_thumb   INTEGER NOT NULL DEFAULT 0,
    purpose     TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS outbound_policy (
    purpose    TEXT PRIMARY KEY,
    allowed    INTEGER NOT NULL DEFAULT 0,
    updated_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS time_estimate (
    day             TEXT PRIMARY KEY,
    planned_minutes INTEGER,
    actual_minutes  INTEGER
);
```

**没有“任务会话表”**：任务名与区间只是查询参数，不落库，因此不会形成“按任务、按时间、按记录”的导出历史。`ai_use_daily` 以“任务 + 日期”为唯一键：学生改判后，即使刷新时结束时间变了，也会命中同一条记录并保留改判；`original_mode` 固定保存机器原判，二次改判不会覆盖。

## 3. 功能一：学习复盘（原「过程存证」）

### 3.1 解决什么

学生在电脑前坐了三小时，合上电脑却说不清这三小时是怎么过去的：是查资料查了两小时、只写了四十分钟，还是反过来。这种模糊不是记性差，而是行为本身没有留下可被观察的痕迹。常见的自我汇报又普遍失真——以为学了三小时，实际有效专注一小时二十分。三个具体表现：

- 说不清自己什么时候状态最好，只能凭感觉安排下一段学习；
- 跨了几天完成的任务，回头想不起卡在哪一步，下次遇到同类问题还是卡；
- 被打断了七八次，但只记得"今天很忙"，不知道代价是多少。

本功能的立场是：**不评价努力程度，也不判断内容是谁写的，只把这段学习是怎么展开的讲清楚。**

### 3.2 怎么做

学生主动创建一个任务会话，选择任务名与时间范围，系统在本地完成四步：

1. **圈定范围**：只读取该区间内的快照；允许学生剔除无关片段。
2. **整理次序**：把查阅、写作、编程、AI 对话等片段排成过程序列。
3. **生成结论**：先算节奏（有效记录、最长连续、动手占比、被打断次数），再给出「值得保留 / 值得留意 / 下次可以试」三块。
4. **本人审阅**：学生确认描述是否贴切，可改时间段、改任务名，再导出 PDF。

导出界面只有一个主动作：**导出文件**。没有“发送给教师”“提交教务处”或“加入待检查名单”。

### 3.3 输出物长什么样

```text
学习复盘（学生本人导出）
任务：课程论文《……》                范围：10 月 18 日—10 月 21 日
生成：2026-10-28 15:34　由本程序依据本机记录生成，导出前请本人核对

有记录的 6 小时 12 分里，动手时间 4 小时 05 分

一、这段时间的节奏
  从 09:00 到 21:20，占比最多的是写作。中间有 3 段没有记录的时间，已分开计算。
  最长的一段连续了 130 分钟。

  值得保留
    最长的一段连续了 130 分钟　从 14:00 到 16:10，中间没有切换到非学习活动
    动手时间占 66%　大部分记录落在写作或编程上，不只是准备

  值得留意
    中途离开 3 次　这些离开共占 95 分钟
    动手前准备了 42 分钟　第一次进入写作是 09:42

  下次可以试
    先写三行，再回头补资料　开工先花五分钟列三条要点，直接开始写

二、过程结构
  查阅资料 → 首次起草 → 中断 → 回到同一文档 → 修改与定稿
  首稿到定稿跨越 3 个自然日；查阅与写作交替 7 次。

三、数据完整性
  10 月 20 日 14:00—15:00 无可用记录，不对该时段作任何推断。
  注：回访次数来自窗口标题，不等于文件保存或修改次数。

四、边界说明
  只描述行为节奏，不评价努力程度，也不判断内容是否为本人所写。
  未识别到的手机端活动不在本说明范围内。
```

默认不包含截图、正文、窗口标题全文和模型原始返回。学生确需保留某条线索时，应逐条勾选，而不是一键全部公开。

### 3.4 能说明什么，不能说明什么

| 能说明 | 不能说明 |
|---|---|
| 过程的时间结构与先后关系 | 是谁在键盘前操作 |
| 查阅、起草、返工之间的大致节奏 | 手机、纸质书籍、另一台电脑上的活动 |
| 同一文档标题的反复出现 | 文件实际修改次数与版本差异 |
| 学生确认后的 AI 使用环节 | 未出现在电脑窗口中的 AI 使用 |
| 哪些时段数据完整、哪些时段缺失 | 作品质量、能力高低或学习态度 |

本地 SQLite 可以被有技术能力的用户编辑，因此本功能**不提供作者身份结论，也不提供内容真实性结论**。它的现实价值是降低回忆成本、让讨论回到具体过程，并减少仅凭文本风格作判断的空间。

如未来确有更强的文件完整性需求，可另行评估本地哈希链与可信时间戳；那会引入新的成本与合规问题，**不纳入本版承诺**。

### 3.5 反滥用设计

- 导出物不带“已验证”字样、系统水印、官方标识或版本号，外观就是学生自己整理的材料。
- 不提供校内提交按钮，不连接评奖、答辩或教务流程。
- 不保存导出历史，不生成“已交／未交”名单。
- 如需统计试用情况，只保留不与任务、时间和身份绑定的本机导出计数，且允许关闭。
- 任何材料都可由学生删改；系统明确标记“学生编辑版”，不把编辑行为描述成违规。

**寒蝉效应仍是残余风险**：如果周围人都开始提交，未提交者可能承受压力。因此学校不得把该材料设为必填项，平台也不配合形成提交清单。

### 3.6 主窗口入口

主窗口右上角提供 **“学习复盘”**：默认带入当前日期，并自动取当天首末记录作为起止时间。学生可改时间段和任务名，先看节奏结论，再决定要不要导出 PDF/HTML。

- 预览使用紧凑版式（指标卡 2×2），避免在对话框里横向滚动；实际导出仍是完整版式。
- 只读一期 `snapshots`，**不创建 v2 表**。
- 没有可用记录时预览仍显示完整性说明，但导出按钮禁用。
- 导出不写任务表、不写外发台账；默认保存到 `data/v2_exports/`，也可另选位置。
- 不包含截图、正文、窗口标题全文。

### 3.7 复用成本：S

复用 `snapshots`、连续段合并与时间轴；只新增本地 PDF 生成和脱敏界面，不需要新增任务表或服务端。无需新增截屏频率，无需读取文档内容。

## 4. 功能二：AI 协作画像与用法回看

### 4.1 解决什么

学生知道“我用了 AI”，却未必知道自己是怎样用的：是先在本地思考再提问，还是让对话窗口代替了整个产出过程。简单统计 AI 使用次数没有意义，真正值得回看的是**人与 AI 的先后关系和交替方式**。

回看的目的是找出“哪种用法下，最后留下的东西更像自己的”，不是自证清白。本功能只回答“这段时间呈现哪种协作模式”，不回答“这个学生是否优秀”。

### 4.2 三种模式的可检查判据

先由学生给当前任务加一个上下文标签（如“操作系统作业”或“竞赛项目”）；在同一上下文内按下列启发式规则判断：

| 模式 | 可执行判据 | 学生看到的解释 |
|---|---|---|
| 先思后问 | 只看**首个 AI 窗口之前**：30 分钟回看窗内累计不少于 10 分钟本地产出；中途短暂切到浏览器不把累计清零 | “AI 对话出现在一段本地活动之后” |
| 边做边问 | AI 窗口与本地窗口在 5 分钟内切换不少于 3 次；中间的“其他窗口”不打断配对 | “对话与产出窗口多次来回切换” |
| 直接要答案 | AI 记录占比 ≥80%，且 AI 样本 ≥10 条、合计 ≥15 分钟、时段覆盖 ≥70%，结束后 15 分钟内无本地产出 | “该时段主要由 AI 窗口构成，后续未见本地产出” |

这些规则只是**可检查的启发式**，不是心理测量。样本、时长或覆盖不足时直接显示“无法判断”，不用少量数据硬贴标签；阈值与实际命中值都会写进判断依据，后续按改判情况调整。

实现上还用两条硬约束避免误伤：**文档与 IDE 的标题不参与 AI 识别**（`deepseek_client.py`、`豆包运营方案.docx` 不会被当成 AI 窗口）；**AI 结束后的观察窗会多读 15 分钟**，防止“范围刚好截在 AI 结束”被误判成直接要答案。

### 4.3 每条结论都必须能回到依据

每次判定展示：

- 支撑它的时间段与压缩后的窗口序列（AI / 本地产出 / 其他）；
- 实际使用的门槛与命中值：交替次数、首个 AI 前的本地分钟数、AI 样本与覆盖比例；
- 数据是否完整：跳过的异常时间记录、样本覆盖率；
- 一个明确按钮：**“这次判断不对，我要修改”**。

学生可以改成任意一种模式，也可以标记为“无法判断”或“未见 AI 窗口”。改判以“任务 + 日期”为键写入本机 `ai_use_daily`，刷新时即使结束时间变化也不会被覆盖；`original_mode` 固定保留机器原判，二次改判不会把学生上次的结论当成机器结论。

### 4.4 呈现方式：按周描述，不做人格标签

```text
本周 AI 协作回看
主要呈现：边做边问（3 个任务时段）
另有：先思后问（2 个任务时段）、无法判断（1 个任务时段）

可回看：周三晚“课程设计”中，AI 与 IDE 在 5 分钟内交替 5 次。
你可以修改这次判断；修改只影响本机记录。
```

模式按周呈现，不跨周累计成“你属于哪一种人”。如果某周数据太少，直接显示“样本不足”，不用旧数据补齐。

### 4.5 主窗口入口

主窗口右上角提供 **“AI 协作”**：

- 默认带入当前日期和当天首末记录，学生可改时段和任务上下文。
- 打开即分析当前范围，展示模式、覆盖率、交替次数、首个 AI 前本地分钟数和压缩后的窗口序列。
- **只看不保存不建 v2 表**；点“保存判断”才写入本机，点“保存我的改判”才更新学生结论。
- 已保存的改判不会因重新分析被覆盖；二次改判保留 `original_mode`。
- 同一窗口下方显示本周已保存判断汇总，只统计同一 ISO 周。

**使用禁区：**

- **不进入任何成绩构成。**
- **不生成跨周的人格标签。**
- **教师端默认不开放；如未来试点，只给课程整体分布，不给个体名单。**

一旦把模式用于奖惩，学生会迅速改用手机或其他窗口规避，数据会失真，而且失真方向恰好是“看起来更自律”。因此它只能用于学生自评与教师改进课程设计，不能用于筛人。

### 4.5 AI 使用声明：申报而不是检测

过程存证可以附带一份由学生确认的声明：

```text
AI 使用声明

使用工具：________（可多选，也可填“未使用”）
使用环节：□ 查概念  □ 理提纲  □ 改语句  □ 生成代码  □ 调试  □ 其他
主要用途：________________________________
本人独立完成的部分：________________________
AI 参与程度（本人估计）：□ 较低  □ 中等  □ 较高
需要说明的情况：____________________________

声明人：________    日期：________
```

其中“参与程度”是学生的自我说明，不是系统计算结果。模板由学生自愿使用，**学校不得把它变成统一的必填项**。教师若需要了解 AI 使用情况，应先说明教学目的和可接受范围，再让学生自主选择表达方式。

### 4.6 复用成本：S/M

应用识别、窗口序列和时间统计都可复用；新增任务上下文、规则引擎、依据展示、改判界面和声明模板。技术难点不在模型，而在把误判处理做完整。

## 5. 功能三：数据台账与数据护照

> 这一章是支撑层，不单独包装成创新点。它让前两个功能可被检查，也让一期“隐私优先”从文字承诺变成可演示的产品事实。

### 5.1 台账记录什么

当前一期唯一明确的对外数据流，是向模型服务发起请求。因此第一版只做**外发审计**，不虚构一个尚不存在的多方授权系统。

每次由本程序发起的请求记录：

| 字段 | 含义 |
|---|---|
| `ts` | 请求时间 |
| `provider` / `model` | 接收方厂商与模型名 |
| `bytes` | 本次请求体大小 |
| `has_thumb` | 是否包含压缩缩略图 |
| `purpose` | 画面识别、日终总结或连接测试 |

不记录提示词全文、图片内容、窗口标题全文或模型原始返回，避免台账本身变成新的敏感副本。

学生可以按日期查看：今天发起了多少次请求、其中多少次带图、发往哪个服务、用于什么。连接测试也要记录，因为它同样是一次外发。

**实盘接入状态**：`AIClient` 已接入台账，但**默认关闭**；关闭时不创建 v2 表、不写记录、不改变一期 AI 行为。主设置窗口已挂 **“设置 → 数据护照…”** 入口，可在界面里开关、导出与清理。也可以用命令行：

```bash
.venv\Scripts\python.exe tools\v2_ledger.py enable
.venv\Scripts\python.exe tools\v2_ledger.py status
.venv\Scripts\python.exe tools\v2_ledger.py passport
```

默认只记录、不拦截；加 `enable --enforce` 后才会按用途开关真正阻止请求。开启拦截后如果台账无法写入，请求会**停止而不是无记录外发**。

### 5.2 撤回的三层真实语义

| 层级 | 能做什么 | 界面应怎样表述 |
|---|---|---|
| 撤回未来 | 拦截模式下关闭某类外发立即生效；只记录模式只改变状态，不会阻止请求 | “停止后续此类请求” |
| 撤回本地 | 一期已支持按日删除快照、总结与相关图片；v2 元数据可在“设置 → 数据护照…”里按日删除，也可用 `tools/v2_ledger.py cleanup 日期 --yes` | “删除本机这些数据” |
| 不可撤回 | 已经到达模型服务的请求无法由本程序收回 | “已外发部分不能由本程序收回” |

第三层必须明示，不能用一句笼统的“随时撤回”带过。正因为已外发部分收不回来，才需要在外发前把粒度压到最低：敏感窗口先拦截、画面指纹先去重、只发送压缩缩略图、日终总结只发送压缩后的文本摘要。

### 5.3 数据护照：一份能拿去给人看的说明

学生可以导出 JSON 或 PDF，内容包括：

```text
数据护照
生成时间：2026-__-__ __:__

本机保存：快照记录、可选图片、日终总结
保存位置：本机 data/ 目录
保留策略：图片保留 __ 天；记录由本人管理
近期外发：画面识别 __ 次，日终总结 __ 次，连接测试 __ 次
接收服务：________；模型：________
外发内容：压缩缩略图／压缩后的文本摘要（按实际记录列出）
拦截规则版本：________
最近本地清理：________
```

这份护照既可给学生本人检查，也可在学生主动选择后给辅导员、信息化部门或评审专家看。它把“程序到底做了什么”从口头说明变成可核对的清单。

**页脚必须写：本台账只覆盖本程序发起的外发，不覆盖用户手动上传到网盘、微信或其他软件的行为。**

### 5.4 复用成本：S

在现有 AI 适配层统一记录请求元数据即可；本地删除已有基础。新增工作主要是 `outbound_log`、查询页和护照导出，不需要改变截屏流程。

## 6. 彩蛋：时间感知校准

### 6.1 解决什么

时间统计告诉学生“实际发生了什么”，但还少了一面镜子：**我原先以为会发生什么。** 很多人并不是完全没有计划，而是持续低估任务、同时高估自己可支配的时间。

每天第一次打开看板时，学生可以用 5 秒填一句：“今天打算学习多久？”日终总结旁边给出实际值，累积成估时偏差曲线。

### 6.2 怎么做

- 输入可跳过，哪天不想填就不填。
- 实际值统计学习与工作类活动的并集，并显示“不是所有前台时间”的口径说明。
- 每周只给一个观察，例如“本周估时普遍高于实际，偏差主要出现在有晚课的日子”。
- 学生可以修改当天的估计，但不修改已经发生的实际记录。
- 不做连续打卡、不断签提醒、不设置 streak，也不在缺填时追问原因。

**主窗口入口**：AI 今日总结卡片右上角提供 **“估时校准”**。选择日期、填预计投入后保存，同时结算当天实际产出；下方显示最近 14 天里偏高、偏低、接近和一致的天数。打开只读取记录，**点保存才创建 `time_estimate` 表**。

它最适合做答辩现场的直观演示：**“我预计三小时，实际一小时二十分”不需要任何技术解释，学生立刻能理解。**

### 6.3 边界与成本

只用于自我认知，不用于教师评价，不生成效率排名。新增一张 `time_estimate` 表、一个输入框和近期文字汇总，主要复用日终统计，成本约为小半天级原型工作量。

## 7. 主动不做的两个选题

### 7.1 新生适应期观察：不做

初看很贴近学工场景，但深入后有三个问题：

1. **与 v1.0 重复过高**。作息规律性、深夜活跃、学习时长趋势，基本就是班级温度计的既有指标换了人群和时间窗。
2. **班级尺度的匿名并不充分**。在二三十人的新生班里，辅导员熟悉学生，叠加宿舍、课表等背景信息后，聚合数字仍可能被反推到个人。`N≥8` 只是最低门槛，不是匿名成立的充分条件。
3. **容易把正常波动贴上问题标签**。入学初期的作息变化和学习节奏波动很常见，不能仅凭屏幕行为推断适应状况。

保留下来的两点价值，不作为独立功能：

- **冷启动基线**：新生没有个人历史，不应直接套用老用户的本人基线；前几周只展示原始事实，不给偏离结论。
- **周末落差**：可以作为 v1.0 专注力体检的一个新增观察维度，但仍只用于本人回看。

### 7.2 竞赛／大创团队过程纪实：不做

1. 多成员实时汇聚需要服务端，与一期“原始数据留在本机”的系统边界直接冲突。
2. 屏幕时间不等于贡献：查文献、想方案、写代码和协调沟通的行为形态不同，按投入分布比较容易系统性误伤。
3. 一旦出现团队分布，挂机保持窗口前台就能改变数据，指标会迅速失效。
4. 给指导教师“是否需要介入”的提示，会把团队内部本可协商的问题变成系统告状。

因此不做团队贡献度、团队排名和个人曲线。若未来只做“团队约定时段是否各自在线”的轻量工具，也应各自本机记录、各自导出，且不属于本版范围。

## 8. 风险与反滥用

| 攻击或误用路径 | 现有设计防线 | 仍然存在的残余风险 |
|---|---|---|
| 学校把过程材料变成必交项，未交者被默认怀疑 | 无提交接口、无提交名单、无官方标识，文档明确自愿 | 校园同伴压力仍可能形成事实上的强制 |
| 通过班级分布叠加宿舍、课表等背景反推个人 | 个体功能优先；聚合时另做可识别性评估，不只检查人数 | 小样本与极端值仍可能暴露个人 |
| 把 AI 协作模式用于奖惩，学生转向手机规避 | 不进成绩、教师端默认关闭、允许改判 | 只要外部另行惩罚，仍会出现策略性使用 |
| 修改本地 SQLite 后导出更好看的过程材料 | 明示不提供作者与内容结论；材料仅作过程说明 | 材料仍可能被不了解边界的人过度信任 |
| AI 窗口标题缺失，模式被误判 | 展示依据、允许改判、样本不足时不判断 | 新型工具与手机端仍会造成系统性盲区 |
| 导出的过程材料泄露课程名、文档名或作息 | 默认脱敏、逐项勾选、本人审阅 | 学生转发后，平台无法控制二次传播 |
| 数据护照被当作覆盖所有软件的安全保证 | 页脚限定只覆盖本程序外发 | 读者仍可能忽略限定语 |
| 功能开关过多，学生机械点同意 | 默认关闭、按功能分别开启、用白话解释后果 | 长期提示仍可能带来授权疲劳 |
| 估时偏差被用于批评学生 | 只在本人界面呈现，不做连续打卡和排名 | 学生本人也可能因偏差产生挫败感 |

这里有一条需要正面承认的原则：**技术上“能聚合”不等于场景上“适合聚合”。** 后续任何班级或课程视图，都要重新评估可识别性、用途和退出机制，不能把 v1.0 的人数阈值当成永久答案。

## 9. 试点与验证

建议只做小规模、可退出的学生侧试点，不先接学校系统。

- **对象**：30—50 名自愿参加的学生，覆盖不同年级与不同 AI 使用习惯。
- **周期**：一个学期；前期只验证本地功能，后期再讨论是否需要课程整体分布。
- **前提**：不与成绩、评奖、评优绑定；参加和退出都不需要说明理由。
- **材料**：功能说明、数据护照样例、撤回操作说明、误判反馈入口。

| 观察指标 | 口径 | 用途 |
|---|---|---|
| 自愿开启率 | 实际开启人数 ÷ 收到完整说明的人数 | 判断学生是否理解并愿意使用 |
| 导出次数 | 仅本机匿名计数，不关联任务、时间和身份，可关闭 | 判断过程材料是否有真实使用场景 |
| 改判率 | 被学生修改的 AI 协作判断 ÷ 全部可判断记录 | 发现规则误判与窗口识别盲区 |
| 信任度问卷 | 试点前后使用同一组白话问题 | 检查“我能看懂、我能控制、我敢导出”是否改善 |

不预设好看的留存率或提升幅度。首轮只建立基线，结果如实报告“预计验证什么”和“实际观察到什么”。

出现以下任一情况应暂停试点：被要求提供个人名单、被要求把导出设为必交、出现未经学生同意的材料二次传播，或改判率显示规则已失去基本参考价值。

## 10. 政策对位：只认领最贴合的部分

2026 年 4 月，教育部等五部门印发《“人工智能+教育”行动计划》（教科信〔2026〕1 号）。本方案只对位少数直接相关条款，不把整份政策都写成自己的功能依据。

| 政策表述 | 本方案的对应设计 | 边界 |
|---|---|---|
| “建设学生数字档案，根据学生能力、特质和爱好，动态优化学习路径” | 学生本人管理过程记录，并用估时偏差回看计划 | 不建设校级学生主档案，不自动替学生决定路径 |
| “探索开展学生学习全过程纵向评价、德智体美劳全要素横向评价” | 只认领其中的“学习过程纵向回看” | 体育、美育、劳动教育等横向要素不在本版范围 |
| “有效防范……学术造假……泄露隐私” | 提供过程说明与自愿申报，减少只凭文本风格判断；提供外发审计 | 不做文本检测，不声称能处理所有学术诚信问题 |
| “有效防范……惰化思维、过度依赖” | 用可改判的协作模式帮助学生回看人与 AI 的分工 | 不推断思维能力，不把某种模式等同为依赖 |
| “规范智能产品进校园管理” | 默认关闭、分项开启、本地优先、分层撤回、数据护照 | 不把自愿界面替代学校应有的管理制度 |

2025 年《教育部等九部门关于加快推进教育数字化的意见》提出“完善结果评价，开展多维度的过程评价、增值评价和综合评价”。本项目能提供的是其中一种**学生侧过程材料**，不是完整的学校教育评价体系。

**明确不在本版范围**：校级数据共享、学生统一管理画像、五育全要素覆盖、课堂行为识别、手机端记录、心理健康判断。

6. **AI 协作入口**（已完成）：主窗口“AI 协作”实时分析、查看依据、改判保存并显示同周汇总；只看不保存不建 v2 表。
7. **估时入口**（已完成）：主窗口“估时校准”对照计划与实际，保存才写 `time_estimate`；打开不建表。
8. **隔离演示**（已完成）：主窗口“演示”用 `data/v2_demo/` 生成四页签看板，不读取真实记录，也不影响实际台账。
9. **试点问卷**（未完成）：小范围试用后收集可理解性、误判与撤回体验。

必须通过的测试：

- 没有数据或识别失败的时段显示“无法判断”，不自动补成学习或未学习。
- 同一文档标题的回访不会被写成文件修改次数。
- 默认导出不含截图、正文和窗口标题全文。
- 导出行为不生成可按人、按任务或按时间回查的历史记录。
- AI 模式改判后，原规则不会在下一次刷新时覆盖学生选择。
- 接入主程序前必须补齐：按日删除 v2 元数据、同步清理对应图片；已外发部分始终显示“不可由本程序收回”。
- 生成过程材料和数据护照时不需要访问学校系统。

## 附录 A：可直接放进答辩稿的三段话

**第一段：这一版解决什么**

一期回答“记录属于谁”，这一版回答“学生能拿记录做什么”。因为数据属于学生，所以学生才有权选择一段过程，整理成材料，也有权知道它是否离开过本机。三个功能共用同一条本地数据管道，不新增学校端个人名单。

**第二段：我们怎样面对 AI 代写争议**

我们不判断一段文字像不像 AI 写的，而是让学生把查阅、起草、返工和 AI 参与的顺序讲清楚。材料不识别作者，也看不到手机端，这些边界会写在纸上。它用于减少误解，不用于给学生定性。

**第三段：凭什么相信我们的隐私设计**

除了承诺，我们给学生一份数据护照：本机存了什么、向哪个服务发过多少次请求、是否带图、用于什么，都能核对。未来的外发可以关闭，本地数据可以删除；已经发出的部分不能收回，我们也会明确说出来。

                           ▼

## 附录 C：用语规范表

> 本表专门用于检查和改写措辞，表中左列是需要避免的表达，不是正文推荐用语。

| 不要说 | 改成 |
|---|---|
| 监控、监督、追踪 | 记录、回看、留痕 |
| 证明、佐证、防伪 | 说明、回放、自述 |
| 不可篡改 | 文件完整性校验／本地可修改的边界说明 |
| 评分、评级、依赖度 | 描述、模式、参照 |
| 预警、异常、需关注 | 变化、偏离本人基线、数据不足 |
| 采集（对人） | 采样（对画面） |
| 一键撤回 | 分层撤回（未来／本地／不可撤回） |
| 修改次数 | 同一文档标题的回访次数 |
| 已认证、已核验 | 学生本人整理、学生确认版 |
